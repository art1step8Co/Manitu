# Онбординг как исчезновение информационного хвоста

Онбординг не заканчивается знакомством с документами. Он заканчивается, когда новый участник может продолжать работу без обязательного восстановления контекста у автора.

В начале:

`H_onboarding > 0`

Участник регулярно вынужден спрашивать:
- что это значит;
- какая версия актуальна;
- почему так;
- кому передавать;
- что делать дальше.

По мере освоения языка и процедур:

`H_onboarding(t) ↓`

## Критерий завершения онбординга

Онбординг считается завершённым, когда участник способен:

1. загрузить актуальное состояние из репозитория;
2. распознать нужную метароль или процесс;
3. конкретизировать метароль под свой контекст;
4. выполнить следующий шаг;
5. записать возникшую дельту;
6. передать состояние следующему человеку/агенту;
7. не обращаться к автору только ради реконструкции уже созданного знания.

То есть:

`H_onboarding -> 0`

или, practically, хвост становится ограниченным только новым неизвестным, а не потерянным старым контекстом.

## Acceptance test

Дать новому участнику только ссылку на GitHub и короткий входной ролик.

Успех:
- он создаёт корректный экземпляр роли (например, своего Маниту);
- выполняет один рабочий цикл;
- делает commit/push;
- другой человек/агент продолжает без повторного объяснения.
